# CodexChat 功能发展分析报告

分析日期：2026-10-10。分析基线：本仓库 0.1.9 的源码与文档。本文区分已实现能力、独立原型和建议功能，开发周期仅用于规划，不是交付承诺。

## 1. 产品方向

CodexChat 的价值是帮助用户找到历史工作、理解项目消耗，并准确回到对应项目继续处理。下一阶段建议优先投入 **全文检索、增量索引、历史导出、项目路径修复和可解释的使用统计**。

本次增加的置顶、确认删除和固定统计栏补齐了基础管理，但“列表能整理”与“历史能检索、复用”仍有距离。参考用户提出的 Codex 桌面端项目/会话管理方式，应延续项目优先、操作状态明确、删除必须确认的体验；本文不把桌面端的内部接口或未经核实的功能当作插件可直接依赖的能力。

## 2. 现有能力与证据

| 模块 | 当前实现 | 已知边界 | 主要依据 |
| --- | --- | --- | --- |
| 项目归类 | 扫描活动、归档 JSONL，依据 `cwd` 分组；可手动添加项目 | 原项目目录不存在时会话被排除；没有路径重映射 | `src/codexSessionRepository.ts` |
| 会话列表 | 标题、更新时间、归档标识、分支状态 | 缺少自定义排序、标签、备注和本地标题 | `media/webview.js`、`src/models.ts` |
| 搜索 | 项目名称/路径；当前项目会话标题/分支 | 不搜索消息正文，不跨项目搜索会话 | `media/webview.js` |
| 查看详情 | 用户、助手、部分工具调用；复制 ID、定位原文件 | 消息内容以转义后的纯文本展示；最多显示 2,000 条记录 | `src/codexSessionRepository.ts`、`media/webview.js` |
| 回到 Codex | 打开项目、新会话、恢复历史；跨工作区保存待交接动作 | 历史跳转依赖官方扩展的内部路由，失败时复制 ID | `src/codexHandoffService.ts` |
| 分支检查 | 展示记录分支和当前分支；恢复前提示不一致；按当前分支筛选 | 没有 worktree 定位和自动切换分支 | `src/gitUtils.ts`、`src/codexHandoffService.ts` |
| Token 统计 | 项目汇总、平均值、占比、输入/输出/推理分项 | 缺少模型、时间范围、每日趋势；不是账户账单 | `src/codexSessionRepository.ts`、`media/webview.js` |
| 置顶 | 项目/会话置顶，状态持久化，按钮立即高亮 | 多个置顶项按时间排序，不能拖动调整顺序 | `src/sessionService.ts`、`media/webview.css` |
| 删除 | 会话和项目数据永久删除，模态确认；项目删除包含隐藏归档 | 仅管理识别成功的本地 JSONL，无回收站，不同步官方数据库/云端 | `src/sidebarProvider.ts`、`src/codexSessionRepository.ts` |
| 固定汇总 | 总览显示全局 Token 和项目数；项目页显示项目 Token 和全局项目数 | 受项目存在性及归档配置影响，不代表所有历史消耗 | `media/webview.js`、`media/webview.css` |
| 刷新 | 文件监听、防抖扫描；置顶/删除直接更新状态，旧扫描不会覆盖操作 | 外部文件变化仍会触发全量扫描 | `src/sessionService.ts` |
| 本地化/诊断 | 中英文、扫描时间/失败数量/警告 | 诊断偏开发者视角，缺少可操作的修复入口 | `src/i18n.ts`、`src/sidebarProvider.ts` |
| 时间统计 | 已有独立 HTML 原型和设计文档 | 未接入插件；不能算作已实现功能 | `doc/项目时间统计-原型.html`、`doc/项目时间统计-原型设计.md` |

这些能力说明插件已有可用的本地管理主流程。后续应复用现有扫描、项目映射和交接服务，避免重复建立聊天客户端和模型调用体系。

## 3. 优先级与投入比较

P0：影响现有能力可靠性的基础工作；P1：建议下一阶段交付；P2：基础完成后的增强；P3：暂缓或需要额外验证。投入以单人熟悉现有项目、含基础测试为前提，单位为人日。

| 建议功能 | 用户价值 | 投入估算 | 优先级 | 主要依赖 |
| --- | --- | --- | --- | --- |
| 增量索引、扫描进度、局部更新 | 会话多时仍能及时显示变化 | 4–7 | P0 | 可靠的文件变更和缓存失效策略 |
| 全局全文搜索 | 按问题、代码或结论找到历史对话 | 5–8 | P1 | 消息索引、后台任务与取消机制 |
| Markdown 导出/选择消息复制 | 把历史成果用于文档、交接和复盘 | 2–4 | P1 | 详情解析、明确导出范围 |
| 本地标题、标签、备注 | 标题无法表达业务背景时仍能管理会话 | 3–5 | P1 | 独立管理元数据 |
| 项目路径重映射、失效项目视图 | 项目移动后历史仍可访问 | 4–6 | P1 | 项目身份与实际工作区路径分离 |
| Token 日期/模型筛选与趋势 | 理解某个周期、项目和模型的使用变化 | 4–7 | P1 | 按事件累计口径去重、模型识别 |
| 详情 Markdown、代码块、长会话分页 | 阅读历史代码和长记录更方便 | 3–5 | P1 | 渲染安全、条目分页 |
| 归档/隐藏/回收站及批量管理 | 整理大量历史而减少误删损失 | 5–9 | P2 | 文件操作兼容性与恢复方案 |
| Codex CLI 续接入口 | 官方扩展跳转失效时仍有续接方式 | 2–4 | P2 | 本机 CLI 能力探测、参数安全 |
| Worktree 和多根工作区支持 | 准确回到会话所在工作副本 | 4–7 | P2 | Git 仓库身份与工作区映射 |
| 活跃时间统计 | 了解项目投入的活动节奏 | 4–7 | P2 | 可解释的事件时间算法 |
| 项目管理元数据备份/迁移 | 更换设备时保留标题、标签和置顶 | 2–4 | P2 | 元数据版本化与冲突规则 |
| 云同步、团队共享、AI 自动总结 | 跨设备/多人协作和自动归纳 | 8–15+ | P3 | 身份、权限、费用、隐私与可靠同步 |

不建议同时开发所有功能。全文搜索和增量索引共享较多基础能力，适合先形成一条稳定链路，再扩展统计和管理。

## 4. 值得优先开发的功能

### 4.1 增量索引与扫描体验（P0）

**场景**：用户历史包含大量 JSONL，Codex 正在持续追加内容。当前扫描逐个读取摘要、首条用户消息和 Token 记录，外部变化可能反复读取未变更的文件。

**最小版本**：按真实路径、大小、修改时间缓存摘要，监听变化后仅重新解析对应文件；新建/删除文件直接更新索引。首次扫描先展示缓存或元数据，后台补齐用量。扫描显示进度并支持取消，切换 Codex 目录时中止旧任务。

**实现建议**：缓存存入扩展 `globalStorageUri`，带结构版本；文件缩短、被替换或解析版本改变时重建。先做完整文件的摘要缓存，再评估从字节偏移量增量读取，避免把多字节字符、半行写入和文件轮转一起引入。

**验收**：置顶不读取源文件；单个会话追加只重新解析该文件；缓存损坏可自动重建；用固定的 100/1,000/10,000 文件数据集记录首次扫描和热刷新耗时，并据测量设定目标，不预先宣称任意规模都能秒开。

### 4.2 跨项目全文搜索（P1）

**场景**：“上次解决数据库连接错误的代码在哪个会话？”标题和分支通常不足以命中具体问题。

**最小版本**：统一搜索项目、标题、用户消息和助手正文；结果显示项目、会话、命中片段和时间，点击定位到对应消息。支持当前项目/全部项目、活动/归档、时间范围；第一阶段采用关键词匹配，暂不引入向量模型。

**实现建议**：索引在扩展宿主后台完成，Webview 只接收有限结果。为每次搜索分配请求标识，旧请求不得覆盖新结果；标题检索可以立即返回，正文索引未完成时明确显示覆盖范围。正文索引与摘要缓存共用文件失效机制。

**验收**：能搜到没有出现在标题里的词；中文输入期间不打断组合输入；切换项目与归档范围结果正确；删除会话后搜索结果同步移除；索引文件保留在本地，可清理和重建。

### 4.3 导出与成果复用（P1）

**场景**：需要把一次排障过程整理到项目文档，或把最终结论交接给同事。

**最小版本**：单会话导出 Markdown、复制单条消息、仅导出用户/助手消息。导出包含标题、项目路径、分支、时间和会话 ID；提供是否包含工具记录和路径信息的选项。

**实现建议**：复用解析器，但导出使用独立读取流程，明确“完整会话”或“当前显示内容”。不能把详情的 2,000 条显示上限悄悄带入完整导出。通过保存对话框选择目标文件，覆盖现有文件时遵循编辑器确认机制。

**验收**：代码块、换行、特殊字符保留；大于 2,000 条记录时完整导出不丢内容；取消保存不写文件；生成内容经过抽样人工比对。批量导出可留到下一阶段。

### 4.4 本地标题、标签与备注（P1）

**场景**：自动标题可能过长或过于泛化，用户希望标记“已解决”“待继续”“重要决策”。

**最小版本**：自定义显示标题、少量自定义标签、一段备注；按标签筛选。置顶仍负责排序，标签负责分类，避免增加多套含义相同的收藏状态。

**实现建议**：新增带版本的独立元数据存储，以数据源身份和会话 ID 为键；显示标题优先本地覆盖，然后使用 `session_index.jsonl`，最后使用首条用户消息。编辑本地元数据不改原始会话。

**验收**：重启后标题、标签、备注保留；外部标题变化不覆盖用户设置；删除会话同步清理元数据；搜索能够命中自定义标题和备注；重复 ID 的跨数据源记录不会串联。

### 4.5 项目路径修复与历史保留（P1）

**场景**：用户重命名或移动项目目录。当前代码会过滤原 `cwd` 不存在的会话，这些历史在插件里消失，用户容易误认为记录丢失。

**最小版本**：增加“失效项目”视图，可继续浏览和导出；允许把旧项目路径关联到新的工作区位置。只读浏览依据原始归属，打开 Codex 使用映射路径，并在恢复前核对分支。

**实现建议**：将“来源项目路径”和“实际工作区路径”分离，保存显式映射；同名目录不可自动合并，路径大小写和平台规则统一使用 `pathUtils`。先支持用户手动映射，再评估 Git 远端/仓库标识辅助建议。

**验收**：移动目录后历史可见；映射后进入正确的新目录；不会改写历史 `cwd`；失效与有效项目的统计范围明确；用户可以解除映射并恢复原分组。

### 4.6 可解释的 Token 趋势（P1）

**场景**：现有总量能展示项目规模，但用户更想知道“这周哪个项目增长最多”和“哪些模型消耗较多”。

**最小版本**：今日/近 7 天/近 30 天/自定义区间；项目和模型筛选；每日总量与输入、缓存、输出分项；缺失数据说明。提供 CSV 导出便于用户自行分析。

**实现建议**：当前每会话总量不能直接按创建日期分摊。需要解析带时间的累计 Token 事件，以相邻累计值的增量归入时间桶；累计值重置、重复事件、恢复会话和未知模型必须有规则。推理 Token 是否属于输出子集应依源数据定义处理，不能直接重复相加。

**验收**：连续累计事件不会重复计数；跨天会话可以按实际事件日期分配；同 ID 的活动/归档副本不双计；未知模型和缺失记录独立标识。只有模型、价格版本、缓存计价口径齐备后才增加费用估算，并标明估算而非账单。

### 4.7 详情阅读与长会话浏览（P1）

**场景**：历史包含代码、表格、长排障过程，目前纯文本和 2,000 条上限影响阅读。

**最小版本**：Markdown、代码高亮与复制代码按钮；工具调用折叠；用户消息目录；详情内搜索；分批加载后续记录。保留“纯文本”作为兼容模式。

**实现建议**：引入可禁用原始 HTML 的 Markdown 渲染器，保留现有 CSP；远程图片不自动加载。解析器提供稳定消息定位标识和分页游标，全文搜索结果可以定位到后续分页。

**验收**：恶意 HTML 不能执行；代码块复制不改变字符；未知事件仍可继续浏览；大文件滚动与加载不会冻结界面；分页无重复或遗漏。

## 5. 中期增强功能

### 5.1 归档、隐藏、回收站和批量操作（P2）

先区分三种语义：隐藏仅改变插件视图；归档需要移动源文件并确认官方存储规则；回收站将文件移到插件管理目录以便恢复。不能把移动 JSONL 宣称为对官方桌面端的完整归档同步。

建议先交付本地隐藏与多选，再评估回收站。批量删除必须给出项目、会话数量和范围；失败应报告逐项结果。恢复需要原路径冲突处理、源目录变化处理和元数据恢复。现有永久删除仍保持明确确认，回收站不能在后台悄悄改变其语义。

### 5.2 CLI 续接与 Worktree 定位（P2）

提供显式的“在终端中继续”，探测本机 CLI 及可用的恢复方式，以参数数组或安全终端输入传入会话 ID，正确设置工作目录。CLI 缺失时给出安装指引，不能直接执行拼接的未经转义命令。

Worktree 支持应把同一仓库的工作副本分组，同时保留各自 `cwd`。恢复时建议正确副本；自动切换分支须检查工作区修改并由用户选择。多根工作区中优先定位已经打开的对应文件夹，避免不必要地重载整个窗口。

### 5.3 时间统计（P2）

现有原型可复用布局，但不能把首尾消息间隔当作真实工作时长：会话可能闲置数天，多会话可能并行，文件修改时间也可能来自复制。

建议分别展示“会话跨度”和“估计活跃时长”。活跃时长按事件间隔阈值分段，提供阈值选择；项目聚合使用区间并集，避免并行会话重复加总。说明时区、跨天分配、缺失时间和截断数据。用已知事件序列验证算法后再接入插件，不把该指标称为准确工时。

### 5.4 备份、键盘与诊断（P2）

备份优先支持置顶、标题、标签、项目映射等管理元数据，采用版本化 JSON 导出/导入，提供合并与覆盖选项；会话正文备份属于单独功能。键盘操作支持上下选择、回车打开、快捷搜索和返回项目，删除快捷键同样需要确认。

诊断页增加“重新扫描”“清理缓存”“打开数据目录”“查看读取失败文件”等入口。分享诊断时只输出版本、计数和脱敏路径，不自动包含会话正文。

## 6. 暂缓的能力与原因

| 能力 | 当前不优先的原因 | 重新考虑的条件 |
| --- | --- | --- |
| 插件内独立聊天/模型调用 | 与现有伴生定位重叠，引入账户、计费和上下文管理 | 用户明确需要独立工作流，并有稳定接口 |
| 默认云同步历史 | 涉及敏感代码、冲突处理和跨机器路径 | 明确的授权、加密与恢复需求 |
| 团队共享完整会话 | 项目代码、终端输出和个人路径可能混入历史 | 先有可选择、可脱敏的导出能力 |
| 自动 AI 总结/向量搜索 | 有额外模型费用，当前全文搜索基础尚未完善 | 关键词搜索覆盖不足有真实数据支持 |
| 强制对齐官方桌面端全部历史 | 本地 JSONL 不一定包含官方所有数据 | 官方提供稳定公开管理接口 |

## 7. 建议实施顺序

### 阶段 A：可靠性与索引基础

巩固 0.1.9 的管理操作，增加多文件部分删除失败、目录链接边界和数据源切换测试；建立可重复的性能样本。完成摘要缓存与单文件更新，保留手动全量扫描作为修复入口。

完成条件：后台刷新不会撤销用户操作，单文件更新可测量，缓存可重建；项目、会话数量和 Token 汇总保持同一口径。

### 阶段 B：查找与复用

交付全局全文搜索、Markdown 导出和本地标题/标签。复用索引基础，使搜索能定位具体消息，导出不受详情显示上限影响。

完成条件：用户从一个正文关键词找到跨项目历史，并能把完整成果导出；搜索覆盖率和索引状态可见。

### 阶段 C：统计与项目连续性

交付失效项目视图、路径映射、Token 时间趋势与详情分页。先验证累计事件的统计算法，再发布成本估算或时间统计。

完成条件：移动项目不会丢失可见历史；统计能够解释来源、时间范围和缺失数据；长会话可完整浏览。

### 阶段 D：规模化管理

根据实际使用反馈选择批量操作、回收站、CLI、Worktree 和元数据迁移。云同步与 AI 总结独立评估，不与基础管理捆绑发布。

## 8. 工程与质量要求

1. **统一状态**：扩展宿主维护事实状态，Webview 的即时反馈在成功/失败回推后收敛；异步搜索、扫描和文件操作都需处理旧结果。
2. **分离存储**：源 JSONL、索引缓存、用户管理元数据分别管理；缓存损坏不能损失标题、标签和映射。
3. **边界明确**：删除只处理身份验证成功的托管文件；项目目录和其他 Codex 数据不受影响；归档或同步能力必须明确实际作用范围。
4. **行为验证**：优先验证真实临时 JSONL、持久化、取消确认、部分失败和并发；避免只靠源码字符串断言证明功能存在。
5. **前端验证**：深色、浅色、高对比主题；窄侧栏；中文输入；长列表固定栏；键盘焦点与滚动保留。
6. **发布一致性**：版本、README、插件说明、变更日志和 VSIX 内实际代码一致；Git 推送不等于扩展市场发布。

建议先通过用户反馈记录“查找成功率、常见搜索词、导出需求、目录移动情况”，默认不上传历史正文或未经授权的遥测。以这些本地测试与明确反馈决定后续功能，而不是仅按界面可增加的按钮数量扩张。
